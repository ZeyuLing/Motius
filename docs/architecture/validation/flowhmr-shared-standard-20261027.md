# FlowHMR 普通模式与精度验证（2026-10-27）

## 配置和测量范围

使用用户提供的完整 750 帧、30 fps 视频，NVIDIA H200，原版 SAM 3D Body，身体及左右手逐帧提取，VGGT 不抽帧，20 步采样、固定种子。计时包含模型加载、跟踪、相机、特征与采样，不包含用户操作；显存为 `nvidia-smi` 对当前进程每秒采样的峰值，不是整卡占用，也不是消费级显卡的最低需求。

| 配置 | 时间 | 进程显存采样峰值 | 说明 |
| --- | ---: | ---: | --- |
| 原普通模式，旧实现 | 366.81 s | 49.78 GiB | 历史测量，详见 productization 报告 |
| 普通模式，原版 SAM 分 8 帧合批及共享流式 VGGT | 117.95 s | 5.11 GiB | 未使用后续加入的 SAM conditioning 缓存 |
| 普通模式，加入 conditioning 缓存 | 108.64 s | 5.11 GiB | 最终代码，完整 750 帧 |
| FP32 前端比较（旧对照） | 672.83 s | 6.95 GiB | 关闭 matmul TF32；此轮 cuDNN 仍允许 TF32 |
| 严格 FP32 前端比较 | 663.29 s | 6.92 GiB | matmul 和 cuDNN TF32 都关闭；与最终普通模式使用同一缓存配置 |

以上两个新测试都没有使用预处理缓存，输入帧与采样设置一致。普通模式保留 SAM 的原始 CPU 裁剪与左右手分别运行；分批不改变输入帧。最新代码进一步复用 SAM conditioning，并在结果中分别记录 `sam_conditioning_optimized` 与 `staged_resources`。相对于未启用该缓存的普通模式，750 帧世界坐标关节平均差 0.708 mm、95 分位 1.100 mm、最大 1.305 mm，身体旋转平均差 0.0085°，手部旋转平均差 0.0105°；差异来源尚未单独归因，不能声称逐位一致。和旧普通模式完整结果比较，帧 ID 一致，世界关节平均差 0.869 mm、95 分位 1.464 mm、最大 5.056 mm；身体与手部旋转平均差分别为 0.024° 和 0.034°。这些差异覆盖了批处理、相机流式计算与缓存等全部变化。

## BF16 说明

默认 `source` 遵循原模型：SAM 检查点配置使用 BF16，当前检查点的骨干包含 551 个 BF16 权重张量；VGGT 在支持的 GPU 上按上游方式使用 BF16 autocast。FlowHMR 动作采样为 FP32。`float32` 比较模式禁用前端 autocast，关闭 matmul 与 cuDNN TF32，使用 FP32 运算；SAM 权重原本以 BF16 保存，升到 FP32 不能恢复丢失的权重精度。

对上表两次完整输出，750 帧 ID 一致，22 个世界坐标身体关节的欧氏距离平均 2.168 mm、95 分位 4.180 mm、最大 10.823 mm；52 个关节的旋转差，身体 22 关节平均 0.083°、最大 1.549°，手部 30 关节平均 0.113°、最大 2.605°。这是固定种子下两种数值设置的输出差异，不是与真实动作标签的误差，也不能证明哪种精度更好。该旧对照的 cuDNN 仍允许 TF32。严格 FP32 与最终普通模式的完整视频对照中，750 帧 ID 一致，世界关节平均差 2.616 mm、95 分位 5.045 mm、最大 11.324 mm；身体旋转平均差 0.088°、最大 1.343°，手部旋转平均差 0.130°、最大 3.252°。默认模式与严格 FP32 分别选择 cuDNN BF16 注意力和 PyTorch FP32 注意力内核，因此差异包含计算精度及内核选择。

## 可迁移运行时

`deploy/flowhmr` 提供 Linux x86_64 NVIDIA PyTorch 25.01 的 Docker 构建上下文、64 个依赖的冻结快照、运行环境检查与 Blender 队列适配器。运行时不包含权重、视频、SMPL-H 或凭据。冻结依赖在独立 Python 环境通过版本、导入、TorchVision CPU 算子和离线 doctor 检查；适配器的挂载与取消已用模拟 Docker 进程测试。使用冻结依赖与打包源码，在同一 H200 的独立 Python 路径实际跑完整视频，得到 108.83 s、5.11 GiB 驱动进程峰值；和常规环境的最终普通模式对照，帧 ID 相同，世界关节平均差 1.634 mm、95 分位 2.449 mm、最大 6.107 mm，身体旋转平均差 0.011°、手部平均差 0.012°。这不是逐位一致；运行和环境中的差异尚未单独归因。

当前测试主机和 GPU 容器没有 Docker/Podman，尚未实际构建镜像、在 Docker GPU 中运行，也未在其他 NVIDIA GPU、Windows、macOS 或 AMD 平台实机验证。不能将这个构建上下文称为已验证的跨平台镜像。详细部署方式及边界见 [运行时说明](../../../deploy/flowhmr/README.md)。

原始 profile 和对比数据位于 `outputs/validation/flowhmr/product-release-20261027/shared-standard-20261027/`；实际 GPU allocator、驱动和输入不同会影响运行时及显存。

## FP16 探索与误差尾部（2026-10-27）

上面严格 FP32 与默认 BF16 的手部最大差 3.252° 出现在第 257 帧（30 fps，约 8.57 s）的左手食指第二关节；第 256–260 帧分别为 3.029°、3.252°、2.262°、1.815°、1.467°。全部 22,500 个手部关节帧中，250 个超过 1°、22 个超过 2°，分别出现在 70 帧和 14 帧。99 分位为 1.045°。这些都是两次推理间的局部旋转差异，不是真实标签误差。

在独立实验副本中将 SAM backbone 和 VGGT aggregator 的计算改为 FP16，保持其他设置和 750 帧不变；这不是生产模式。输出所有数值数组均为有限值，耗时 109.58 s，驱动进程峰值 5.11 GiB。相对严格 FP32 的手部局部旋转平均差 0.058°、95 分位 0.217°、99 分位 0.439°、最大 1.511°；22,500 个手部关节帧中 18 个超过 1°，无超过 2°。22 个身体关节的世界坐标距离平均差 1.554 mm、最大 6.926 mm。相同基准下，BF16 手部平均差 0.130°、最大 3.252°。这段视频显示 FP16 更接近严格 FP32，但不能据此断言一定更接近真实动作；严格 FP32 使用 PyTorch 注意力内核并关闭 matmul/cuDNN TF32，FP16 使用 cuDNN 注意力且允许 cuDNN TF32，比较包含算子和计算精度等差异。实验只验证输出有限，并未监控全部中间激活，无法证明 FP16 对其他输入或所有中间操作都不会溢出。

运行原始 profile、实验摘要和数值对照保存在 `outputs/validation/flowhmr/product-release-20261027/shared-standard-20261027/fp16-experiment/`，误差尾部记录为同目录 `precision-tail-analysis.json`。原模型 checkpoint 的 SAM backbone 权重以 BF16 保存，转换到 FP16 不会恢复原 checkpoint 已经损失的精度。
