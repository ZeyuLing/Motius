## 采用的优化

1. **并行图像准备。** 四个有界 CPU worker 独立读图、缩放和转换，按输入顺序汇总，保留原始 JPEG/PIL/ToTensor 计算。此项从约 9.14 s 降至 2.84 s；不同图像尺寸、padding 和顺序的像素逐位一致测试通过。
2. **释放 AMP 权重缓存。** 模块移回 CPU 时，外层 autocast 仍可能持有其 GPU dtype 转换副本。现于模块生命周期边界清理该缓存，当前模块内部的微批仍复用转换结果。完整相机计算期间释放约 1.82 GB 累计缓存，单项峰值分配从 5.39 GiB 降到 **3.72 GiB**。
3. **实测选择已安装的精确 SDPA 内核。** 首个足够长的真实全局注意力输入上，对 PyTorch 默认和 cuDNN 各做一次热身与三次计时。只有 cuDNN 快超过 10% 才选用；短序列或 CPU 保持原路径。未改变 softmax 范围、精度、权重或采样率。

本次自动选择实测：默认内核每次 23.60 ms，cuDNN 15.56 ms，选择 cuDNN，无回退。单独控制实验中，跨帧块计算合计从 50.82 s 降至 37.45 s，完整 VGGT 单项从 73.14 s 降至 **53.42 s**。单项环境与完整流水线的加载/计时边界不同，因此完整流水线实测的 51.57 s 优先用于产品耗时描述。

在真实键长度 444750、16 heads、head dim=64、4096 查询的 BF16 微测中：默认 Flash 为 23.57 ms，Efficient 为 57.74 ms，cuDNN 为 16.37 ms。Efficient 更慢，未纳入自动候选。微测本身不能替代上述全片验证。

自动模式若 cuDNN 不可用、显存不足或后续形状不支持，会在**单次注意力操作内部、残差尚未写回之前**退回 PyTorch 默认路径。不会重跑已原地修改部分输入的整个 Transformer。选择耗时与回退原因会写入结果 metadata；其他显卡由实际输入测量决定，不硬编码 H200 加速比例。显式 `cudnn` 模式的错误不被静默隐藏。

## 使用和验证

CLI 的 `--lightweight` 和 Blender 0.2.6 的加速模式默认选择自动策略。标准模式保留原始相机计算路径。

```bash
python tools/infer_flowhmr.py /path/to/checkpoint /path/to/video.mp4 \
  --lightweight --vggt-attention-backend auto --vggt-frame-interval 1 --profile
```

84 项回归测试通过，1 项跳过。覆盖图像顺序/像素/padding、完整键可见性、内核选择和操作内回退、不可用 cuDNN、阶段清理与插件派发。实际 Blender 4.5.3 的进度协议验证通过，两种 ZIP 的 manifest 验证记录附在 JSON。
