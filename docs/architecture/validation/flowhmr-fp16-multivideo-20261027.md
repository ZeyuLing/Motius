# FlowHMR 混合 FP16 多视频验证

实验采用 NVIDIA H200、Motius FlowHMR checkpoint、种子 0、20 步动作采样、全部身体和双手特征及逐帧 VGGT 相机。普通模式使用官方 SAM；不改变输出帧数。上游示例为 24 fps 输入，按统一管线转换为 30 fps，因此输出 151 帧；网球视频转换后 313 帧；用户视频为原始 750 帧 / 30 fps。两段额外视频分别运行自动检测与跟踪，帧 ID 一致，但未保存逐帧检测框，无法证明两次选人轨迹逐位相同；用户视频复用同一选人轨迹。均使用同一随机种子的严格 FP32 输出为数值参考，不是真实动作标签。

FP16 是混合执行：SAM backbone 使用 FP16，VGGT aggregator 使用 FP16 autocast，其他运算依旧按照模型自身类型执行。SAM 发布权重原本为 BF16，不能恢复其保存之前的精度。严格 FP32 禁用前端 autocast，关闭 matmul 和 cuDNN TF32；它使用 PyTorch 注意力内核，FP16 使用 cuDNN，数值差异包含内核、精度和重复运行的影响。

| 视频 | 输出帧 | 手部局部旋转平均 / P95 / 最大差 | 身体关节世界位置平均 / 最大差 |
| --- | ---: | --- | --- |
| FlowHMR 上游示例 | 151 | 0.0028° / 0.0099° / 0.0244° | 0.811 / 2.307 mm |
| 网球 | 313 | 0.0053° / 0.0121° / 0.3370° | 1.260 / 13.118 mm |
| 用户完整视频 | 750 | 0.0579° / 0.2122° / 1.5321° | 1.555 / 7.085 mm |

以上对照采用带中间激活检查的 FP16 测试：实验副本直接覆盖模型配置，因此其旧版 profile 显示 `frontend_precision: source`，应以实验脚本的覆盖和本报告为准；正式集成代码正确记录为 `float16`。正式集成代码重跑用户视频时，手部平均 / P95 / 最大差为 0.0611° / 0.2270° / 1.5567°。由于没有真实动作标注，不能将 FP32 当成绝对真值或用这些数据证明视觉准确率。

## 中间激活检查与边界

监测 SAM 和 VGGT 的可挂钩叶子模块 CUDA 浮点输出并汇总数值类型、非有限值、最大有限绝对值和接近 FP16 上限的数值。三段视频分别记录 60,805、135,143 和 300,631 次模块输出；未观察到非有限值或监测报错。每段有 20–24 个 TorchScript 模块不支持前向钩子，函数式操作和网络外模块也未全部覆盖，因此不能证明所有中间计算及所有输入均不会溢出。

VGGT 第一个 patch encoder block 的 LayerScale 输出保留 FP32，三段视频中最大值约 144,748–145,320，超过 FP16 上限 65,504；相邻可观测 FP16 输出最大约 46,752–46,944。此路径不能简单整体转换为 FP16。本模式保留该 FP32 中间计算，并在加载 SAM 权重前验证骨干权重有限且在 FP16 表示范围内。现有管线还检查相机和特征输出有限。

结果、原始 audit JSON、脚本及 profile 位于 `outputs/validation/flowhmr/product-release-20261027/shared-standard-20261027/fp16-multivideo/`。当前只在单个 H200 和三个视频验证，默认仍是上游精度，FP16 需用户明确选择；不同 GPU、驱动或输入需要继续验证。OOM 工作区重试不会改变已选精度或删帧。

## Blender 环境方案

[Motion2MixamoRig 扩展文档](https://github.com/MaxLiu22/Motion2MixamoRig/blob/main/blender_extension/README.md)描述的默认方案是在 Blender 外创建 Python 运行时：插件内一键下载 uv、Python 和依赖，单独下载模型权重；Blender 自身不加载 PyTorch。它也支持高级用户指定已有虚拟环境。项目文档称自动运行时仅在 Apple Silicon 实测，Windows CUDA 需要自备虚拟环境。

Motius 当前的桌面路径同样是 Blender 调用外部 Python，并不需要 Docker；但目前需要用户手动配置外部 Python 和 Motius 项目路径，尚没有参考项目的一键运行时安装。已有 Docker 构建上下文仅是可选的 Linux NVIDIA 部署方式，不是已验证的桌面安装包。

## 低显存模式完整用户视频

同一选人轨迹和 750 帧下，Fast SAM / 严格 FP32 为 643.11 s、进程显存峰值 8.50 GiB；正式接入的 Fast SAM / FP16 混合为 99.98 s、6.28 GiB。两者身体关节世界位置平均 / 最大差为 1.523 / 6.842 mm，手部局部旋转平均 / P95 / 最大差为 0.0571° / 0.2119° / 1.5695°。FP16 在带监测的完整视频运行中记录 233,233 次模块浮点输出，没有观察到非有限值；24 个 TorchScript 模块不能直接挂钩。此计时来自另一轮不带钩子的正式代码，不应与监测轮的耗时混淆。
