# FlowHMR Windows and NVIDIA runtime compatibility

The 0.2.13 extension detects GPU compute capability with `nvidia-smi` before installing the isolated environment. It selects the pinned PyTorch 2.7.1 / torchvision 0.22.1 CUDA 12.8 wheels for Blackwell (including RTX 50), and retains PyTorch 2.6.0 / torchvision 0.21.0 CUDA 12.4 for earlier architectures. The CUDA 12.8 Windows and Linux CPython 3.12 wheels were checked against the official PyTorch index. The GPU driver is supplied by the user. NVIDIA lists 570.65 as the Windows driver accompanying CUDA 12.8; compatibility-mode minimums are different, so the runtime probes actual kernels rather than blindly rejecting a driver version.

Before downloading model weights, the runtime checks that PyTorch exposes a CUDA device, that the installed wheel includes a kernel architecture in the GPU's compute-capability family, and that matrix multiplication and the TorchVision CUDA NMS operator actually execute on each visible device. The check reports missing drivers, incompatible builds and kernel failures; inference preflight also detects incompatible externally supplied PyTorch builds. An automatic setup with both Blackwell and pre-Volta physical GPUs is rejected rather than selecting an unverified mixed-architecture binary. Device visibility is ultimately controlled by CUDA / `CUDA_VISIBLE_DEVICES`.

Tests simulate Windows paths, NVIDIA driver detection, RTX 30 / 40 / 50 and H200 profile selection, mixed GPUs, missing `nvidia-smi`, missing Blackwell kernels and successful Blackwell probe dispatch. Batch-size scheduling and out-of-memory retry tests remain unchanged; they never silently reduce frames or switch model precision. Actual H200 CUDA 12.4 / PyTorch 2.6.0 and CUDA 12.8 / PyTorch 2.7.1 matrix multiplication and CUDA NMS probes both succeeded in separate isolated environments; no end-to-end model inference was run with the latter. A Windows GitHub Actions smoke test runs the installer and mocked device tests without a GPU.

**Limits:** no physical Windows or RTX 50 machine was available. Simulated architecture selection and kernel dispatch do not prove that PyTorch 2.7 / CUDA 12.8, the entire model, the Blender interaction or performance works on a particular RTX 50 card. H200 measurements on CUDA 12.4 are not RTX 50 benchmarks. A driver update or a separately configured compatible external Python may be needed; older GPUs that do not support original BF16 are explicitly rejected for that precision, with FP16/FP32 available as user-selected alternatives. Different PyTorch / CUDA versions may change floating-point outputs; there is no bitwise-equivalence claim.

Primary references: [PyTorch previous versions](https://pytorch.org/get-started/previous-versions/), [NVIDIA CUDA architecture support](https://docs.nvidia.com/datacenter/tesla/drivers/cuda-toolkit-driver-and-architecture-matrix.html), [CUDA 12.8 release notes](https://docs.nvidia.com/cuda/archive/12.8.0/cuda-toolkit-release-notes/index.html), and [NVIDIA compute-capability query](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/compute-capabilities.html).
