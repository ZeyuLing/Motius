# FlowHMR 计算等待压缩实测 · 2026-10-26

Motius 0.3.11 / Blender 扩展 0.2.7。只计算模型和软件处理的等待，不计用户选视频、选人、点击按钮或结果播放。**本轮没有达到 60 秒。** 后端实测从 111.99 秒降至 104.30 秒；三角色重定向、接地和排列另需计算，不能从总等待中隐藏。

## 同视频、同硬件完整测量

用户视频 25 秒、30 fps、完整 750 帧；H200，PyTorch 2.6.0a0+ecf3bae40a.nv25.01，CUDA 分配器限额 6 GiB，CPU 4 线程。新进程，文件和内核磁盘缓存已热，无视频特征缓存。保留每帧身体和两只手、VGGT interval=1、全部全局 K/V、原始权重和 dtype、20 步采样、seed=0、TF32=False。没有缩短视频、降低图像分辨率、减少关键帧、减少手部特征或新增量化。

| 后端阶段 | 原路径对照 | 本轮优化 |
| --- | ---: | ---: |
| 动作网络加载 | 2.30 s | 2.29 s |
| 转码 | 1.79 s | 1.80 s |
| 检测跟踪 | 8.59 s | 8.77 s |
| VGGT | 51.62 s | 50.93 s |
| SAM 加载与特征 | 44.49 s | 37.30 s |
| 其中 SAM 特征提取 | 42.07 s | **34.85 s** |
| 动作采样与解码 | 1.28 s | 1.29 s |
| 完整后端计时，含必要读写与框架开销 | **111.99 s** | **104.30 s** |
| 含 Python 导入的进程时间 | 114.53 s | 106.84 s |

SAM 提取时间降低 17.1%，后端总时间降低 6.9%。这是一次完整候选/对照测量，不是多次测量的延迟分布。上一次 0.3.10 后端结果为 111.81 s，与本轮对照接近。

整个后端峰值：分配 **4.483 GiB**、保留 **5.607 GiB**；按秒采样驱动显存 **6434 MiB（6.28 GiB）**；CPU RSS **10.79 GiB**。6 GiB 分配器限额不包含 CUDA 上下文等显存，也不代表与 Blender 图形界面同时运行时能塞进 6 GiB 显卡。没有消费级显卡的实测结果。GPU 原有 1546 MiB 服务未停止，实验结束后只剩该服务。

## 已接入统一架构的修改

1. **只跳过无消费者的最后一次 MHR 预测。** 身体和双手 decoder 的所有中间预测、关键点更新、六层网络及最终归一化 token 都保留。最后的手框由检测 token 单独产生，继续用于两只手的真实网络推理。通用 SAM decoder 默认仍预测完整输出。
2. **保留中间几何，只省去其无用的输出。** 中间 MHR 仍计算全部顶点和关节以产生相同的关键点；Fast conditioning 不再翻转/投影/返回无人使用的完整网格，也不再每层将 faces 从 GPU 读回 CPU。普通 SAM 网络输出不变。
3. **缓存网络常量，而非视频结果。** extractor 持有当前冻结模型的无效关键点提示、初始姿态嵌入和设备端射线网格缓存；射线仍按每帧的 K 和仿射框重新计算。释放 extractor 时清空缓存。没有缓存身体/手部视频特征来排除它们的耗时。
4. **三角色共享 Blender 场景推进。** 独立角色在同一个 frame_set 后分别测量真实变形网格，各自求解接触并烘焙，再共享逐帧场景更新验证全部结果。所有 750 帧、所有角色、接地后检查均保留。约束、驱动、跨对象依赖、未知处理器或不支持的修改器触发原串行流程；出错恢复动作、action slot 和相关属性。

网络目录仅放网络的可选输出接口和计算；缓存生命周期、GPU 裁剪、合批、特征捕捉仍由原生 pipeline 管理，没有引入 vendor 源码。可通过 `FlowHMRPipeline.from_pretrained(..., lightweight=True, preprocessor_kwargs={'sam_optimize_conditioning': False})` 保留本轮优化前的 Fast conditioning 路径。

## Blender 实际计算与效果对照

Blender 4.5.3，原有三角色场景，Y-Bot、Xbot、Michelle，完整 750 帧。新旧流程读同一份动作输入；未保存覆盖原场景。

| 实际 Blender 测量 | 原串行流程 | 共享场景更新 |
| --- | ---: | ---: |
| 默认线程配置：三角色接地，含逐帧网格验证 | 157.01 s | **64.62 s** |
| `--threads 4`：三角色接地，含逐帧网格验证 | 22.91 s | **16.72 s** |
| `--threads 4`：三角色重定向 | 4.14 s | 4.06 s |

全部 **1,990 条动画通道**的关键帧时间和值逐位相同（670 + 670 + 650），不是只检查脚踝或少量抽帧。接地异常时恢复全部角色的实际 Blender 测试也通过。

本机容器 CPU 限额 16 核，宿主暴露 192 个逻辑 CPU；Blender 默认线程池发生过量调度。`--threads 4` 是单独测量的启动条件，插件不能通过修改 render.threads 将已经启动的全局任务池变成四线程，因此不把这部分收益宣传为插件自动获得的加速。

在四线程 Blender 中，实际执行 UI 的 **Animate and Ground All Characters** 操作（包括三角色重定向、完整接地、排列及 UI 状态处理）耗时 **21.14 s**。后端 104.30 s 与该 21.14 s 是分开测量的，相加约 125.44 s，另有 Python 启动、结果导出和进程桥接等开销；不能将这个和称为已测得的端到端总时钟，也不能声称总计算等待已低于 60 s。

## 数值差异，不能称逐位无损

本轮优化与同机原路径的检测框、750 帧相机 RT 和 K **逐位相同**。最终动作存在以下差异：

| 对比 | 世界关节平均差 | 世界关节最大差 | 旋转平均差 | 旋转最大差 |
| --- | ---: | ---: | ---: | ---: |
| 本轮优化 vs 同次原路径 | 1.376 mm | 6.742 mm | 0.01129° | 0.71233° |
| 原路径 vs 同输入重复运行 | 0.753 mm | 6.576 mm | 0.01217° | 0.71936° |
| 本轮优化 vs 原始仓库完整输出 | 1.440 mm | 4.984 mm | 0.03300° | 1.20226° |

重复对照复用相同的相机/框，仅用于测量未优化 SAM 与动作网络自身的运行差异，**不作为新视频推理速度测量**。优化版相对原路径的身体/左手/右手 token 最低余弦分别为 0.9999999999995、0.995304、0.998759；身体 token 最大绝对差 4.77e-6。不能用平均相似度掩盖个别手部帧差异。

网络依赖和精度设置保持一致，微型 decoder 对照证明跳过最终预测时 normalized token 逐位一致、所有中间更新仍执行；变化相机和仿射框的射线缓存测试也逐位一致。但完整网络包含非确定性几何算子，**这些结果不能证明所有输出数值完全相同或真值精度不下降**。最大差接近原路径重复波动，不意味着所有统计指标都落在重复对照之内；例如世界位置平均差更大。没有真人动捕真值，保留上述完整差异与原路径选项。

## 尝试后未设为默认的方案

| 实验 | 结果及取舍 |
| --- | --- |
| 16 帧原始合批 | 原分配策略在 6 GiB 预算下 OOM。 |
| 常量/无用输出优化 + 16 帧，expandable segments | 64 帧热测 2.41 s，分配 5.59 GiB；未做本方案完整 750 帧质量与消费级显卡验证，未设默认。 |
| `torch.compile` backbone | 64 帧从 3.18 s 到 2.91 s，但首次批次 61.89 s；手部最低余弦约 0.989，未采用。首次编译没有藏到计时之外。 |
| 精简 MHR 仅关节依赖顶点 | 可降低权重显存，但改变 conditioning 内部几何模块的存储形状与完整网格输出契约，保留实验，未合入生产网络。 |
| 固定稀疏矩阵预合并 | 64 帧 2.68 s，与常量优化 2.66 s 没有明显收益，未修改生产 TorchScript。 |
| backbone CUDA Graph | 在 6 GiB 预算下 OOM。 |
| decoder CUDA Graph | 实际捕捉失败，未将不完整或退化方案设为默认。 |
| 官方 FlashAttention-3 Hopper BF16 内核 | 真实长键形状微测约 14.43 ms，当前 cuDNN 约 16.05 ms；只是单算子约 10% 改善，不是完整 VGGT 加速，更不是消费级支持或质量验证。未修改生产依赖。 |

这些实验不能称为已证明的全局性能极限。当前主要瓶颈仍是完整 VGGT 相机阶段和其后依赖相机条件的 SAM 身体/手部提取；本轮没有用减少观测或降低精度换取 60 秒的表面数字。

## 验证与复现

86 项回归测试通过、1 项跳过；真实 Blender 进度协议、750 帧三角色通道对照、异常回滚和真实 UI 操作通过。标准与加速扩展 ZIP 的 Blender manifest 均验证通过。

完整后端命令沿用 `tools/validate_flowhmr_fast_sam.py --variant fast --frames 750 --vggt-memory-mode streamed --memory-budget-gib 6 --sam-frame-batch-size 8`，对照额外加 `--sam-conditioning-baseline`；资源参数与[上一次完整验证](flowhmr-vggt-20261026.md)一致。`tools/profile_flowhmr_extreme.py` 与 `tools/profile_flowhmr_extreme_attention.py` 保存隔离实验实现，实验不会自动成为生产默认。

[测量与身份 JSON](flowhmr-extreme-20261026.json)。原始证据在 `outputs/validation/flowhmr/extreme-20261026/`，包含完整输出、逐帧误差 CSV、时间/显存日志、失败实验日志、校验后的压缩档和 Blender 对照脚本。安装包在 `dist/flowhmr_blender/motius-flowhmr-0.2.7-{standard,accelerated}.zip`。
